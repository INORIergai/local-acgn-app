## 本轮落地

### 1. DoH 兜底解析（对标 Kazumi 2.4.5 的 DoH/ECH）

- **新文件** `utils/media-sources/doh.js`：
  - 4 个固定白名单 DoH 端点，**国内优先**：阿里 `dns.alidns.com`、腾讯 `doh.pub`，境外兜底 Cloudflare / Google；
  - **仅 https**、端点不接受外部传入、查询参数用 `URL.searchParams` 设置（不拼接）；
  - `isBlockedIp()` 拒绝 localhost/环回/私网/CGNAT/链路本地/组播/保留地址，查询结果里的私网 IP 一律丢弃。
  - 实测：国内端点 23~160ms 返回公网 IP（www.dm5.com → 36.150.28.207 等），境外端点本网络不可达（约 5s 超时，故排后面）。
- **`engine.js::grab()`** 加第三路：当「代理→直连」都失败（典型 DNS 污染）时，用 DoH 拿到公网 IP，通过 undici `Agent({connect:{lookup}})` 连该 IP（TLS SNI 仍用原域名），成功则返回，失败静默回原错误。正常路径零额外开销；`opts.doh === false` 可关闭。

### 2. 订阅 schemaVersion 门禁（对标 ani 6.4.1）

- `engine.js` 新增 `FACTORY_MAX_VERSION = {web-selector:2, json-api:1, rss:1}` 与 `schemaSupported()`：
  - 上游定义若带 `schemaVersion`/`version` 且高于本引擎支持上限 → **跳过、不覆盖**已有可用源，计数 `skippedSchema`；
  - 无版本字段的旧定义兼容；非数字版本拒绝。
- `refreshSubscription()` 同时补了**路径边界校验**：订阅返回的相对路径必须落在 `OVERRIDE_DIR` 内，拒绝 `../`、绝对路径、盘符（修掉原有的潜在越界写入）。

### 3. Bangumi 冲突逐条选择 UI —— 确认已存在，未重复建设

`public/js/bangumi-panel.js` 的 round185 B2 已实现完整逐条对比：`GET /api/bangumi/diff` 列冲突/云端独有/本地独有 → 每条选「保留本地/用云端」→ `POST /api/bangumi/apply` 应用。后端 `routes/bangumi-sync.js` 的 `/diff`、`/apply` 与 `utils/bangumi-sync.js::diffFrom/applyConflicts` 均就绪。round182 记"CinemaVault 无逐条 UI"已过时，本轮不改动。

## 诚实边界

- DoH 兜底用公开 DNS JSON 端点（非 ECH），不能对抗 SNI 封锁本身；仅解决 DNS 污染/劫持。Kazumi 的 ECH 更彻底，但需底层 TLS 改造，本轮未做。
- 静态/逻辑验证为主；DoH 兜底"实际救回被污染域名"的场景未能在当前网络直接构造（系统 DNS 未被污染），只验证了端点可用、解析正确、两路失败后兜底路径的调用条件。
- Mimosa 多次对本轮新文件/改动报 `命令注入`/`路径穿越` 误报（静态规则不识别 `new URL`/`String()` 模式），已按建议改为常量端点 + `searchParams` + 路径边界校验后通过；仍无完整安全审计，不宣称项目绝对安全。
