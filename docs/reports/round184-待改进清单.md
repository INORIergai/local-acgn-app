## 一、A 档：追番核心链路（继续做，ROI 最高）

### A1 自动选源（tier 分阶段）— 当前唯一还"必须手点"的环节

- **现状**：`match-online` 已按 `tier` 排序（`engine.js:186`），但选哪条源仍需用户逐条点「挂载」（`series-view.js:182/328`）。
- **对标**：Animeko `MediaAutoSelector` — tier≤0 精确匹配瞬时选中，5s 无果放宽到模糊，15s 再放宽。
- **做法**：`match-online` 返回结果后按 `tier` 升序 + 命中集数最多者自动预选第一条，弹窗给「换一个源」兜底；tier=0 且集数≥1 时跳过弹窗直接挂载。
- **成本**：小（纯决策层，接口不动）。**收益**：把"点追番→看"从 4 步压到 1 步。

### A2 失败隔离五态 + 验证码 WebView 救回

- **现状**：`engine.js` 里 `captcha` 关键字 **0 处**，只有 `try/catch` 吞错，无 pending/success/error/noResult/captcha 状态机。
- **对标**：Kazumi 五态隔离 + 验证码开 WebView 让用户过；Animeko 状态机 + 限流退避 + 源黑名单。
- **做法**：`searchOn/episodesOf` 返回值加 `state` 字段；captcha 判定（响应含验证/挑战特征）后弹内嵌 WebView；连续失败 3 次的源写本地黑名单 24h 冷却。
- **成本**：中。**收益**：现在"搜不到"分不清是源挂了、被墙了、还是要验证码，用户只能瞎试。

### A3 `json-api` 工厂执行分支

- **现状**：`engine.js` grep `json-api` **0 结果** —— 规则文件存在但无执行分支，等于写了不能用。
- **做法**：补受限 JSONPath 取值（禁 `[?()]`/`..`/切片/函数调用），POST RPC 模式支持 `稀饭动漫 Next.json` 那类。
- **成本**：小-中（沙箱要写对，别开了个 RCE 后门）。**收益**：规则表达力一次跃升，直接多解锁一类源。

### A4 在线播放路径下的弹幕/字幕/OPED 继承未验收

- **现状**：round173g 只验过本地影片路径；在线 `showVideoPlayer` 走同函数但**从未给过验收证据**，弹幕按标题匹配、字幕走外挂文件，在线路径下大概率失效。
- **做法**：真机跑一遍在线播放，逐项核对弹幕拉到/字幕可切/OPED 可跳/进度续播，缺什么补什么。

## 二、B 档：追番管理与同步

### B1 状态流转补 onHold / abandoned + 分组视图

- **现状**：3 态（追番中/计划看/已完成），grep `onHold|abandoned` **0 处**。
- **对标**：Kazumi 6 态（在看/想看/搁置/看过/抛弃）+ 收藏库排序筛选。
- **成本**：小（加枚举值 + 筛选条）。

### B2 Bangumi 冲突逐条选择 UI

- **现状**：`pull 建基线 → push 覆盖较新者`，无逐条决策。round173e 唯一遗留"部分"项。
- **对标**：Animeko `BangumiConflictChecker`。
- **成本**：中（要做一个 diff 列表 UI）。**收益**：兑现 OAuth 双向同步的完整价值。

### B3 换源后进度继承

- **现状**：进度以本地 `episodeId` 为主键，换源重挂后 `sourceUrl` 变了但 episode 行不变（这点其实还好），**真问题是**未以 Bangumi `episodeId` 为主键，跨库/重建番剧会丢。
- **做法**：episode 表加 `bangumiEpisodeId`，进度双键映射。

## 三、C 档：下载 / 离线（三家差距最大的维度）

### C1 一键推夸克离线 404

- **现状**：round173h 降级为「复制磁力→手动转存」，推夸克接口 404。
- **判断**：需要重新抓夸克 Web 端接口签名，属于反爬对抗，**投入产出比低且不稳定**，建议维持手工转存。

### C2 BT 边下边播 / 离线缓存

- **状态**：round173:213/216 已明确不做（体积/稳定性）。
- **除非用户解禁**，否则不排期。

## 七、建议排期

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | **A1 自动选源** | 用户当初质疑的正是"为什么还要手动"，这是最后一块拼图 |
| 2 | **A4 在线路径弹幕/字幕验真** | 可能已有隐性 bug，先验再修，避免误判"已完成" |
| 3 | **A2 失败五态 + 验证码救回** | 决定"源挂了"和"要验证"能否区分，直接影响可用源数量感知 |
| 4 | **A3 + E2 json-api 分支 + 版本门禁** | 规则表达力与订阅稳定性，同一片代码 |
| 5 | **B1 状态流转** | 小改动，体感明显 |
| 6 | **B2 Bangumi 冲突 UI** | 中成本，补齐同步闭环 |

> 一句话：**v6.7.0 已经能"搜到源、挂上集、播出来、记住进度"，差的只是"不用手点"（A1）和"搜不到时知道为什么"（A2）。**
