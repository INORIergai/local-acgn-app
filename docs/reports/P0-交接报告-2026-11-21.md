## 4. 提交前必须知道

1. **工作区不是干净的基线。** 本次会话开始前，`public/js/app.js`、`public/cloud-reader.html`、`public/comic-reader.html` 等文件已经是修改状态（`git status` 初始快照可见）。按路径提交会把这些历史未提交改动一起带入。提交前请先看 `git diff`，确认可以接受；若必须只提交 P0，需要用交互式暂存（`git add -p`）逐块挑选。
2. **不要格式化代码。** 这些文件是 CRLF（`app.js`、`server.js`、`library.html` 等）。跑 Prettier/ESLint `--fix` 或做行尾转换会产生整文件 diff。Git 的 `CRLF will be replaced by LF` 警告是仓库 `core.autocrlf=true` 的既有行为，可忽略。
3. **`style.v2-backup.css` 的 diff 是行尾噪音。** `git diff --ignore-cr-at-eol -- archive/public-cleanup/style.v2-backup.css` 输出为空；该文件仅移动位置，内容未变。
4. **不要 `git add docs/reports`。** 该目录下有二十多张历史未跟踪 PNG（`_r160-*.png`、`_comfy-*.png`），只加上面点名的两个 md。
5. **不要提交 `config.test.json`。** 它未纳入版本控制，且含真实 TMDB/AI Key；`config.json` 同理。
6. 提交后如需运行验证，用隔离库并显式禁用扫描（见 §5），不要直接 `node server.js` 连生产库。

## 8. 已知限制（不阻塞提交）

- 合并后 45 个脚本共用一个加载单元，任一脚本在**加载期**抛异常会中断后续脚本（改造前是逐文件继续）。因此保留 `CV_NO_BUNDLE=1` 作为排查开关。
- `sanitizeHtml()` 目前放行 `<img>`（简介富文本需要），会允许外链图片/追踪像素。P1 可限制 `img.src` 只允许站内路径与已知图床。
- 手工 `?v=` 已从 4 个页面删除，构建戳由服务端注入；直接双击打开本地 HTML（file://）不会加戳，需通过服务运行。
