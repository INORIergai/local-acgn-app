## 1. 首次连接（setup overlay）

### 01 一屏手输 URL 可接受，但"只给输入框"不可接受
- **问题**：首连页只有一个 `etServerUrl` 输入框 + 「立即连接」，没有历史地址、没有局域网发现、没有扫码、没有试连进度。
- **证据**：`android/app/src/main/res/layout/activity_main.xml:125` 单输入框；`:138` `btnConnect`「立即连接」；`:150` 只有一行静态说明。`setupOverlay` 内部再无 `RecyclerView`/`ListView` 之类历史列表。
- **影响**：新用户必须先在电脑上查到 IP 再手打 `http://192.168.x.x:3517`，这是全 App 的唯一入口，失败一次就流失。
- **建议**：
  1. **局域网自动发现**（成本 M）：桌面端已有 HTTP 服务，加一个 UDP 广播应答（`3517` 上收 `CINEMAVAULT_DISCOVER`，回 `{name,port,https}`），壳侧广播 2 秒收结果，直接把找到的 IP 渲染成可点卡片（"客厅台机 · 192.168.1.7:3517"）。零输入即连。
  2. **历史地址 + 最近 3 个**（S）：`SharedPreferences` 已有 `KEY_SERVER_URL`，改成 `StringSet` 保留 3 条，冷启动直接列出，点一下就重连。
  3. **试连状态要可见**（S）：`btnConnect` 之后立刻置为 `disabled` + 进度环 + 三阶段文案（"连接服务器 → 校验影库 → 载入封面"），失败时保留已填内容，不要清空。
  4. 穿透地址（`https://xxx.trycloudflare.com`）作为第二 Tab「外网访问」，说明"无需加端口"。现在的做法是把两种形态塞进同一行 hint（`:150`），用户根本分不清该填哪个。
- **成本**：M（1 项 2）、S（3/4）。自动发现是 L，但可以放到 1.1。

### 02 原生覆盖层与网页风格割裂
- **问题**：`setupOverlay` 是 `LinearLayout` + 原生 `TextView`/`EditText`，颜色来自 `colors.xml`；而 web 层是 Matinee 暗金 + 衬线标题 + 玻璃拟态。两套字体、两套圆角、两套按钮。
- **证据**：`activity_main.xml:98-151` 全原生控件；`themes.xml:3` 用 `Theme.MaterialComponents.DayNight.NoActionBar`；web 侧 `tokens-v5.css` 的 `--font-display: "Songti SC"...`、`--r-2: 10px`。原生侧没有 `colors.xml` 里的暖夜色定义（只有 `bg_dark #0B0E14` / `accent_gold #E5A93C` 两个能对上）。
- **影响**：用户看到"一个网页应用"之前先看到"一个 Android demo 表单"，第一印象与桌面端的打磨成果不符（Aesthetic-Usability：第一屏粗糙会拖低后续所有容错）。
- **建议**：不要重画原生页，改为**壳只做容器**：本地内置一个 `setup.html`（复用 `tokens-v5.css` + 暗金按钮），用同一个 `WebView` 加载，原生 overlay 只在 WebView 完全没加载起来时兜底。这样字号/圆角/动效与主站天然一致，且改文案不用发版。
- **成本**：M。

### 03 说明文字对比度 4.00:1，且是最关键的排障文案
- **问题**：连接失败时那句"15~30 秒完成域名注册同步"是用户唯一的自救线索，但它是 `#6B7280` 小字。
- **证据**：`activity_main.xml:151` `android:textColor="#6B7280"`；`:129` 输入框 hint 同色；背景 `@color/bg_dark = #0B0E14`。实测对比度 **4.00:1**（WCAG AA 正文需 4.5:1，该文本约 12sp，属正文）。
- **影响**：暗光/低亮度下这句几乎读不清，而它恰好解释"为什么点重试还连不上"。
- **建议**：正文改 `@color/text_secondary`（#9CA3AF on #0B0E14 = **7.61:1**），并把这句话从"灰字段落"升级为**带进度的解释卡**：`正在等待穿透域名生效（约 15–30s）` + 倒计时进度条 + 「仍在等待 / 改用局域网地址」两个按钮。
- **成本**：S。

## 2. 导航与信息架构

### 04 37 个桌面入口 → 5 个 Tab，中间缺一层
- **问题**：桌面侧栏 37 个 `.nav-item`，移动端 Tab 只有 5 个（影片/推荐/新作/收藏/更多），「更多」把剩下 32 个平铺进抽屉。
- **证据**：`grep -c 'class="nav-item' public/library.html` = **37**；`library.html:989-1004` 五个 `m-tab`；`mobile-nav.js` 全文 228 行，`nav` 复用的仍是侧栏 DOM（`:96` 只造一个 `<h3>` 分组标题）。
- **影响**：想进「漫画」「设定」「AI 工作台」的用户要在 32 项长列表里扫；抽屉无搜索、无折叠、无最近使用。
- **建议**：抽屉做**两级**：先固定 6 个高频（影片/动漫/漫画/小说/演员/设置），余下按 `sb-sec-name` 分组折叠（默认收起），顶部加抽屉内搜索框（400ms 防抖，纯前端过滤 `.nav-item` 文本即可）。目标：任意入口 ≤2 次点击。
- **成本**：M。

### 05 返回路径基本可预期（值得保留），但有两处例外
- **问题**：原生 `OnBackPressedCallback` 做了四级兜底（全屏视频 → 原生 overlay → web 弹层 → 历史），逻辑是好的；但 `webView.evaluateJavascript` 是**异步**的，且 SPA 里 `pushState` 次数为 **0**，所以"详情抽屉关闭"与"页面历史"不同源。
- **证据**：`MainActivity.java:469-540` 的 `checkModalJs`（含 `#mainSidebar.open` / `#playerModal.show` / `#readerView.show` / `#detailModal.show` / 兜底 `.modal.show`）；`grep -c pushState public/js/app.js` = **0**；`:528` 双击退出窗口 2000ms。
- **影响**：连按两下返回时，第二下可能在 JS 回调返回前就触发 `canGoBack()` → 直接退出应用，用户感觉"返回键会突然退出"。
- **建议**：在 `handleOnBackPressed` 入口先 `evaluateJavascript` 完成后才计时（当前已如此，但双击阈值 2000ms 在弱机型上偏短），并把阈值提到 **2500ms**；更重要的是给 `#detailModal`/`#mainSidebar` 打开时 `history.pushState({ui:1})`，让返回键与 UI 层级天然对齐（也顺手修了"网页内返回"）。
- **成本**：S。

### 06 搜索入口弱
- **问题**：搜索只改占位符，没有独立搜索态；且有 4 个视图（推荐/漫画/小说/新作）直接把 `.toolbar` 整块 `display:none`，这些页面在手机上**完全没有搜索入口**。
- **证据**：`mobile-nav.js:184-188` 只改 `placeholder`；`mobile.css:419-422` `body[data-mview="guess"] .toolbar, ... {display:none}`。
- **影响**：在「漫画」页想搜一部漫画，必须先切回「影片」甚至打开抽屉。
- **建议**：把搜索提为**全局能力**：TabBar 中间的「更多」改成「搜索」独立 Tab（或 `更多` 抽屉顶部固定一个搜索框），点击后进入全屏搜索 sheet，含"最近搜索 / 热门标签 / 分类筛选"。四个被隐藏 toolbar 的视图保留一个 44px 的悬浮搜索胶囊。
- **成本**：M。

## 3. 可达性（拇指区 / 44dp 热区）

### 07 浮动齿轮与 TabBar 打架（有算式）
- **问题**：原生齿轮固定 `marginBottom=84dp`，不感知安全区；TabBar 是 `58px + env(safe-area-inset-bottom)`。
- **证据**：`activity_main.xml:25-37`：`layout_marginBottom="84dp"`、`44dp×44dp`、`layout_marginEnd="16dp"`、`alpha="0.6"`；`mobile.css:31` `height: calc(var(--m-tab-h, 58px) + env(safe-area-inset-bottom))`；`:67` `--m-tab-h: 58px`。
- **影响**：手势导航（inset ≈ 24–32dp）时 84 − (58+24) = **2dp**，齿轮刚好压在 TabBar 上沿；3 键导航（inset 48dp）时 84 < 106，齿轮**直接盖住 TabBar 顶部 22dp**，会挡住"更多"或"收藏"的点击。`alpha=0.6` 又让它像禁用态。
- **建议**：不再用固定 dp。改为 `FrameLayout.LayoutParams` 动态设置：`marginBottom = dp(58) + insets.bottom + dp(12)`（用 `ViewCompat.setOnApplyWindowInsetsListener`）；或干脆**删掉原生齿轮**，把"切换服务器地址"收进 web 的「设置」页一级入口（原生只在 `setupOverlay`/`errorOverlay` 里出现）。后者顺手解决了风格割裂。
- **成本**：S。

### 08 热区不达标的清单（< 44dp）
- **问题**：多处自定义控件高度落在 28–38px，且没有用 padding 撑热区。
- **证据**：
  - `.player-modal .player-foot .btn { height: 30px }` — `round-motion-extras.css:843`
  - `.player-progress { height: 6px }`（`:hover` 才 9px）— `round-motion-extras.css:866,876`
  - `.progress-slider { height: 5px }` — `comic-reader.html:289`
  - `.btn { padding: 7px 14px; font-size: 13px }` ≈ 31px 高 — `comic-reader.html:90`
  - `.rs-*` 设置面板行高 40px — `reader-settings.css:88`
  - `.m-tab-label { font-size: 9px }`（横屏）— `mobile.css:492`
- **影响**：拇指按住 5px 进度条的概率接近 0；30px 的播放器按钮在行走中误触/漏触率高。
- **建议**：统一"**视觉高度 ≠ 热区高度**"：所有 `<button>`/可点 `div` 加 `position:relative` + `::after { inset:-8px; }` 扩到 ≥44px；进度类改 `height:6px` 但**命中层 `padding-block: 12px`**（视觉用内层 fill 画）。TabBar 横屏字号从 9px 提到 11px，靠减 padding 腾空间。
- **成本**：S。

### 09 弹窗按钮位置
- **问题**：`.modal-content` 没有 sticky footer，`player-foot`/`detail` 底部操作都在文档流里。
- **证据**：`library.html:596` `.modal-content` 直接包 `player-head/player-stage/player-foot`；`mobile.css` 无 `position:sticky` 命中。
- **影响**：详情弹窗在 390×844 上一屏装不下，用户滚到底才看到「播放/收藏」，而封面大图又占掉首屏。
- **建议**：`.modal-content` 改三段式 `header / scroll-body / footer`，footer `position:sticky; bottom:0`，主 CTA「播放」+ 次操作「收藏/标记」固定在底部 72px 内。同时把详情封面在手机上从大图改 3:4 缩略 + 信息并排（省 200px 首屏）。
- **成本**：M。

## 4. 可读性

### 10 字号阶梯本身是对的，但手机端没吃到
- **问题**：`tokens-v5.css` 已经把 21 档收敛到 6 档（11.5 / 12.5 / 14 / 17 / 22 / 40），口径正确；问题是**手机端大量组件仍用字面量**，且横屏/阅读器里出现 9px。
- **证据**：`tokens-v5.css:22-27`；例外：`mobile.css:492` `font-size: 9px`、`comic-reader.html:79` `max-width:420px` 的 title 在 ≤860 时压到 160px/13px（`:352`）、`library.html:614-617` 播放器按钮 `font-size:11px`（`kbd`）、`playerTime` `12px`。
- **影响**：中文 12.5px 在 390px 上可读，11.5px 只适合数字/拉丁（tokens 注释里自己也写了），但 `--t-micro` 被用在中文元信息上（"总影片/总大小"角标、卡片副标），中文笔画在小字下糊。
- **建议**：定一条**手机端字阶**（写进 `mobile.css` 顶部，`@media (max-width:860px)`）：`micro→12px 仅限数字`、`caption→13px`、`body→15px`、`title→18px`。中文信息一律 ≥13px。横屏 Tab 9px→11px。
- **成本**：S。

### 11 暗色对比度：暗色没问题，浅色皮肤不达标
- **问题**：三套皮肤的次级文字对比度差异很大。
- **证据**（实算，WCAG 相对亮度公式）：
  - aurora `--text-muted:#8B95B4` on `#0B0E14` = **6.49:1** ✅
  - matinee `#9C9CA8` on `#0B0E14` = **7.11:1** ✅
  - classic 浅色 `#7C7466` on `#FAF8F1` = **4.35:1** ❌（正文需 4.5）
  - 原生说明文字 `#6B7280` on `#0B0E14` = **4.00:1** ❌（见 03）
  - 阅读器正文 `#f3ecdd` on `#12100c` = **16.15:1** ✅；其 dim 62% 混色 = **6.64:1** ✅
- **影响**：白天用户在 classic 皮肤下看元信息（年份/时长/番号）会吃力；这是唯一一套不达标的皮肤，也是桌面默认皮肤。
- **建议**：classic 的 `--text-muted` 从 `#7C7466` 提到 `#6B6455`（≈5.2:1），或用 `color-mix` 与 `--text` 混到 78%。顺带核对 `theme-v4.css:306` 的第二套 muted 值。
- **成本**：S。

### 12 玻璃拟态：131 处 `backdrop-filter`，手机上是在赌 GPU
- **问题**：`backdrop-filter: blur()` 在移动 GPU 上单价很高，且叠在暗底上会把正文衬成"灰雾"。
- **证据**：`grep -rc backdrop-filter public/css/*.css` 合计 **131** 处；`round90-glass-readability.css:14` 已经把 AI 面板从 62% 提到 **88%** 不透明度（说明这个问题已经踩过一次）；播放器底栏 `rgba(255,255,255,.08)` + `blur(28px)`（`round-motion-extras.css:830-838`）在视频画面上做毛玻璃——滚动/播放时每帧都要重采样。
- **影响**：中低端机播放页掉帧、滚动发灰；暗底上半透面板上的 12px 灰字在低亮度下几乎消失。
- **建议**：`@media (max-width:860px)` 内做**降级表**：`backdrop-filter: blur()` → `none` + 不透明度提到 0.82–0.9（视觉仍是"深色面板"，只少了模糊）；只保留 3 处真正撑门面的玻璃（TabBar、播放器底栏、详情 header）。给出实测目标：首屏可交互 <1.5s、滚动 ≥50fps。
- **成本**：M。

### 13 长中文标题截断策略不统一
- **问题**：卡片标题、toolbar 标题、播放器标题的截断方式各不相同。

### 14 表格/元数据密度

- **成本**：S。

## 5. 状态设计

### 15 空状态：只有 emoji，没有下一步
- **问题**：所有空态是"大 emoji + 一行 `--text-muted` 文字"，没有按钮、没有解释、没有回到有内容的地方。
- **证据**：`app.js:3783 / 3900 / 3919 / 4937 / 4947 / 4976 / 5049 / 5067 / 5309` 共 9 处 `empty-state`；`style.css:1754-1759` 定义只有 `.icon{font-size:46px}`；例如 `:4976` "暂无文件"。
- **影响**：用户不知道是"没数据"还是"加载失败"，只能反复下拉刷新。
- **建议**：`empty-state` 升级为三件套：**图标（SVG，不用 emoji）+ 一句人类语言（"这部片子还没扫描到封面"）+ 一个动作按钮**（重新扫描 / 导入 / 去设置）。区分"真空"与"筛选后为空"（后者给「清除筛选」）。
- **成本**：S。

### 16 加载态：主网格没有骨架，只有极光条
- **问题**：骨架屏只做在「新作」和「猜你喜欢」两处，主力「影片」网格在换页/首屏时是空白 + 顶部极光进度线。
- **证据**：`polish.css:1512-1533` `.nr-skeleton-*`；`round113-p8.css:20` `.av-skel-board`；`round-view-loader.css` 全套 `nvl-*`（V3 极光线 / V1 盘动 / V2 走带，按 250ms/800ms 分级）；`mobile.css` 内**无任何 skeleton**。
- **影响**：手机上 4G/弱 WiFi 首屏 1–3s 只有一条细线在动，用户会以为白屏；且 view-loader 的三级动效本身在低端机上是额外绘制。
- **建议**：给 `movie-grid` 做 **9 张卡片 shaped skeleton**（与真实卡片同尺寸，避免加载完跳动 → 直接消掉 CLS）；`nvl-*` 在 `@media (max-width:860px)` 只保留 V3 细线，关掉 V1/V2。
- **成本**：S。

### 17 错误态：15–30 秒说明是好文案，但位置和出口不对
- **问题**：`errorOverlay` 全屏盖住 WebView，只有「立即重试」「修改服务器地址」两个出口，没有"用离线缓存继续看"。
- **证据**：`activity_main.xml:39-84`（`tvErrorTitle`「影库连接未就绪」/`tvErrorMessage` 穿透说明/`btnRetry`/`btnSwitchAddress`）。
- **影响**：出门在外没网，App 直接变成一张错误页，即使本地已缓存封面/进度也不给看。
- **建议**：错误页分三档：①首次连接失败（保持现有）；②已有历史连接失败 → 显示「离线模式（可看已缓存元数据）」+「重试」；③穿透等待中 → 倒计时。文案里补上"你的影库地址是 `xxx`"（让用户能自己核对），并给「复制地址」按钮。
- **成本**：M。

### 18 更新提示：系统样式 + 不可取消，与应用风格割裂
- **问题**：更新弹窗是 `AlertDialog`（继承 `Theme.MaterialComponents.DayNight`），下载进度是不可取消的 `ProgressDialog`。
- **证据**：`MainActivity.java:691-699`（`setCancelable(false)`，按钮"立即更新"/"稍后再说"）；`:701-707` `ProgressDialog` + `STYLE_HORIZONTAL` + `setCancelable(false)`；主题 `themes.xml:3`。
- **影响**：这是用户在整个 App 里唯一会看到的"另一个 App"；且下载 100MB 期间无法取消、无法后台，切走就断。
- **建议**：①改用应用内 `update.html`（复用暗金设计）+ 原生 `DownloadManager` 后台下载（带通知栏进度）；②`ProgressDialog` 至少 `setCancelable(true)` 并给「后台下载」；③失败态给「重试 / 用浏览器打开」。
- **成本**：M（后台下载）/ S（可取消与失败文案）。

## 6. 阅读器 / 播放器沉浸体验

### 19 进度条在触屏上不可用（本次审计最硬的问题）
- **问题**：三处进度条都是"5–6px 高 + 只绑 `onclick` + 拇指只在 `:hover` 出现"。触屏没有 hover，所以**拇指永远不出现**，且**不能拖动**，只能点。
- **证据**：
  - 播放器：`library.html:618-620`（`#playerProgress` 是 `div`）；`style.css:1289` `height:5px`；`round-motion-extras.css:866` `height:6px`、`:876` 仅 `:hover` 变 9px、`:887-900` 伪元素拇指 `scale(0)`，仅 `:hover` 时 `scale(1)`；唯一交互 `app.js:13813 / 14253` `playerProgress.onclick`。
  - 漫画：`comic-reader.html:760` `onclick="seekPage(event)"`；`:289` `height:5px`；`:306` `:hover::after` 才显示 14px 拇指。
- **影响**：想跳到第 38 分钟，必须在 350px 宽里精确命中 5px 高的条（命中率 ≈ 5/844）。这基本等于"没有 seek 功能"，用户只能靠双击快进 10s 反复点。
- **建议**：把三处统一成一个 `media-scrubber` 组件：
  - 命中层 `height: 44px`（透明），视觉层 6px；
  - `pointerdown/move/up` 全套拖拽（`setPointerCapture`），拖动时视觉层升到 10px 并放大时间气泡；
  - 拇指**常驻**可见 12px（不要靠 hover）；
  - 拖动中暂停 `timeupdate` 回写，松手才 seek（避免卡顿）。
- **成本**：S（播放器 + 漫画各 30 行 JS）。

### 20 播放器两套控件并存 + 底栏拥挤
- **问题**：`<video controls>` 自带一条系统控制条（含它自己的进度条、全屏、音量），下面又有一条自定义 5px 进度条 + 6 个按钮。
- **证据**：`library.html:604` `controls playsinline`；`:610-622` `player-foot` 内 6 个按钮（PotPlayer / 弹幕 / 上集 / 下集 / 顺序连播 / 队列）+ 进度条 + 时间；`mobile.css:362` `.player-foot { flex-wrap: wrap }` → 390px 上必然换 2–3 行；`mobile.css:369` `#playerVideo { max-height: 52vh }`。
- **影响**：视频只占 52vh，下面 2–3 行控件把屏幕塞满；两个进度条让用户不知道拖哪个；`⏮ 上集` 这类文字按钮在手机上信息密度过高。
- **建议**：
  1. 手机端 `controls` 保持开启（系统条的全屏/画中画是用户熟悉的），**删掉自定义 5px 条**，避免双份；
  2. 底栏从 6 按钮压到 **3 图标 + 1 溢出 `⋯`**（上集/下集/更多），「PotPlayer」「队列」进 `⋯` sheet；
  3. 视频高度 `52vh → calc(100dvh - 56px)`（顶栏 56 + 系统条），把手机变成"播放器优先"而不是"信息优先"。
- **成本**：M。

### 21 状态栏隐藏后的退出成本 & 手势零提示
- **问题**：全屏后没有任何"如何退出/如何操作"的一次性提示；漫画还主动隐藏了左右箭头（`opacity:0`），页面上不留任何可点线索。
- **证据**：`MainActivity.java:160-170` 透明状态栏 + `LAYOUT_FULLSCREEN`；`comic-reader.html:628-641` `.zoom-controls, .page-nav-arrow { display:none }`、`.page-nav { width:32%; opacity:0 }`（不可见但可点）；`mobile-gestures.js` 提供双击/滑动，但**全仓无"首次使用提示"**（无 `localStorage` 引导标记）。
- **影响**：新用户不知道可以双击快进、侧滑翻页、下滑关闭；看不到箭头就以为"翻不了页"，只能去找工具栏。
- **建议**：首次进入阅读器/播放器各弹一次 **1.5 秒的 gesture coach mark**（半透明文字 + 小箭头，`localStorage` 记 `seen`）："双击左右边缘 ±10s · 上滑音量 · 下滑关闭"。漫画把左右 32% 隐区在**第一次点按**时闪现 300ms 箭头。
- **成本**：S。

### 22 双击快进的反馈有 OSD，但幅度不可预期
- **问题**：双击快进 10s，长按渐进（5s→10s→50s→5min→10min），两套逻辑并存；OSD 用的是同一个 `#playerOsd`。
- **证据**：`library.html:604` 的 `title` 里把这条写成了**给桌面键盘用户**的说明（"空格=播放/暂停 · ←/→=±5s（长按渐进 5s→10s→50s→5min→10min）…"），`library.html:606` `player-osd`；`mobile-gestures.js` 侧双击是 10s 固定。
- **影响**：桌面 5s / 手机 10s / 长按 5s–10min，同一手势三套刻度，用户无法形成肌肉记忆；且 OSD 显示在视频中央，恰好挡住字幕。
- **建议**：手机上统一为 **双击 ±10s、上下滑 ±20% 音量**，长按拖动才做渐进；OSD 从中央移到**靠上 1/3**（避免盖字幕），并加"±10s"箭头动效而非纯文字。桌面 `title` 里的键盘说明不要出现在手机上。
- **成本**：S。

### 23 漫画：窄屏双页与"隐区翻页"
- **问题**：双页/跨页拼合按钮在 ≤860px 被隐藏（只能进设置抽屉开），而 390px 下双页每页仅 ~190px。
- **证据**：`comic-reader.html:628-634` 隐藏 `#btnDualPage`；`:691` 按钮「📖 单页」；`:716` `#comicStage{display:flex;gap:6px}` 两张 `img` 并排；`reader-settings.js:111-113` 设置项 `dual` 仍然可选。
- **影响**：用户在设置里开了双页，回到 390px 竖屏看到两张挤在一起的小图，还得再进设置关回去。
- **建议**：设置项加**视口守卫**：`matchMedia('(min-width:600px)')` 不满足时禁用「双页」并显示"横屏或平板可用"；或者竖屏下把双页改成**上下叠（伪双页）**。同时把"翻页方式/单双页"的当前值回显在工具栏按钮上，而不是只有一个「📖 单页」。
- **成本**：S。

### 24 阅读器用 `100vh` 而不是 `100dvh`
- **问题**：`body`/`.reader-container` 都是 `height:100vh` + `overflow:hidden`。
- **证据**：`comic-reader.html:39,45`；`novel-reader.html` 同构（`:39` 附近 `height:100vh`）。
- **影响**：在带地址栏的浏览器里（用户可能用浏览器打开同一套页面），工具栏收起时底栏（`position:fixed; bottom:0`）会被地址栏挡；Android 分屏/折叠屏切换时高度突变。
- **建议**：`100vh → 100dvh`（保留 `100vh` 作为 fallback 行在前），并给工具栏/底栏继续用 `env(safe-area-inset-bottom)`。
- **成本**：S。

### 25 小说排版基本合格，行宽偏窄
- **问题**：正文 18px / 行高 1.8 / 最大宽 700px，桌面 `padding:80px 20% 100px`；手机覆盖成 `padding:14px 16px` + 17px。
- **证据**：`novel-reader.html:118-119`、`:130`、`:332-336`。
- **影响**：390px 减 32px 内边距 = 358px，17px 字号 → 每行约 **21 个汉字**，比舒适区（28–34 字）偏短，翻页频率偏高。
- **建议**：手机端 `font-size:17px` + **左右各 12px**（+8px 行宽），并开放"紧凑/舒适/大字"三档（`reader-settings.js:66` 已有 `fontSize` 选项，把默认 18 改成按屏宽自适应）；同时把 `--t-micro` 的页码/时间改成 13px。
- **成本**：S。

- **问题**：全部移动适配都在 `max-width:860px` 内，768 平板拿到的就是大号手机：单栏 + 底部 TabBar + 44dp 齿轮；861–1080 才回到桌面侧栏压缩态。

### 27 折叠屏无适配

## 8. 动效与性能取舍

### 29 桌面动效全量搬到手机，只关了 2 条
- **问题**：56 个 CSS 里 **172 条 `animation` + 410 条 `transition`**；`mobile.css` 里"关动效"的只有 2 行。
- **证据**：统计命令 `for f in public/css/*.css; do grep -c "animation:"; done` → 172 / 410；`mobile.css:497-498` 仅 `.sidebar` 与 `.m-tab` 的 `transition:none`；`round-view-loader.css` 的三级加载动效（V3/V1/V2）在手机全开；`polish.css:1121` 只关了 `.player-stage::after` 一处。

- **建议**：写一个 `@media (max-width:860px)` 的**移动降级表**（新增 `mobile-motion-budget.css`，只覆盖不删源）：

  3. 直接 `animation:none`：`nvl-v1/v2`、`companion`（桌宠）、`aurora` 极光背景、`shimmer`；
  4. 统一 `will-change` 只在 3 处（弹层/滑动层/进度）。
  验收：`Settings > 开发者 > GPU 渲染条` 无持续红条；滚动 50fps。
- **成本**：M。

## 9. 无障碍

### 30 语义标签近乎为零
- **问题**：`library.html` 1105 行、上百个可点元素，只有 3 个 `role`、16 个 `aria-label`、1 个 `aria-live`，**0 个 `aria-current`**；`activity_main.xml` 只有 1 个 `contentDescription`。
- **证据**：`grep -c 'role=' public/library.html` = 3；`grep -o 'aria-[a-z]*' | uniq -c` → `aria-label:16, aria-modal:2, aria-live:1, aria-expanded:1, aria-controls:1`；`grep -c contentDescription activity_main.xml` = **1**（就是齿轮那一个）；`grep -c aria-current` → 0。
- **影响**：TalkBack 用户听到的是"按钮"、"图片"、"表情符号"；Tab 当前页无 `aria-current="page"`，导航后不知道自己在哪；`m-tab-glyph` 是 emoji（🎬），会被读成"电影摄影机"。
- **建议**（按投入产出排序）：
  1. Tab 5 个：`role="tab"` + `aria-selected` + `aria-current="page"`，glyph 加 `aria-hidden="true"`，label 用 `aria-label="影片库"`（已经有了，补前两套属性）；
  2. 卡片：`role="button"` + `aria-label="{片名}，{年份}，{评分}"`；播放器 6 按钮补 `aria-label`（"上一集"、"下一集"、"播放队列"），去掉 `kbd` 里的 `P`/`N`；
  3. 进度条：`role="slider"` + `aria-valuemin/max/now` + `aria-valuetext="12:34 / 1:45:00"`，加 `tabindex="0"` + 方向键；
  4. 原生 `ImageView` 齿轮已有 `contentDescription`，但**图标是系统 `ic_menu_preferences`**（一个齿轮线条图标），换成品牌图标并给 `contentDescription="切换影库服务器"`。
- **成本**：M。

### 31 系统字体缩放对页面无效
- **问题**：所有字号是 `px`，且 WebView 未设 `setTextZoom`，系统"字体大小"滑块对网页完全无效；原生 `sp` 只影响 overlay 那几行。
- **证据**：`grep -c setTextZoom MainActivity.java` = **0**；`tokens-v5.css:22-27` 全 px；`activity_main.xml:111` 等原生文本用 `sp`。
- **影响**：老年用户/低视力用户把系统字号调到最大，进到影库后一切照旧——这是最容易招致"无障碍不及格"投诉的一条。
- **建议**：①`setupWebView()` 里加 `settings.setTextZoom(100)` 明确锁死（避免系统缩放把 px 布局撑破）**但**同时②在「设置 → 显示」里提供应用内"界面字号：标准/大/特大"三档，实现方式是在 `<html>` 上加 `data-textsize`，`tokens-v5` 的 6 个变量整体 ×1.15/×1.3。这样既可控又不被系统缩放破坏布局。
- **成本**：M。

### 32 触觉反馈覆盖不全
- **问题**：只有返回键关弹窗、音量键翻页会震动。
- **证据**：`grep -c performHapticFeedback MainActivity.java` = 1（`:534` 附近）；web 侧无 `navigator.vibrate`。
- **影响**：手机上"翻页成功/收藏成功"没有物理确认，用户会重复点击（尤其漫画翻页）。
- **建议**：在 `mobile-gestures.js` 里给"翻页/收藏/拖动进度条停止"加 `navigator.vibrate(10)`（Android WebView 支持），iOS 忽略。
- **成本**：S。

## 10. 移动端 3 个最高性价比改造

### ① 把"进度条"做成真正能拖的组件（S 成本，P0 收益）
- 现状：播放器 `style.css:1289` 5px、`round-motion-extras.css:876` hover 才长高、`app.js:13813` 只有 `onclick`；漫画 `comic-reader.html:760` 同样只有 `onclick`。
- 改法：一个 `media-scrubber` 组件，**44px 命中层 + 6px 视觉层 + 常驻 12px 拇指 + pointer 拖拽 + 拖动时间气泡**，播放器与漫画共用。
- 为什么最值：这是唯一"**功能上等于缺失**"的问题（点不中 = 不能跳转），而修复只需 2 个文件各约 30 行，且不改任何视觉语言。
- 验收：390px 真机上，从第 1 分钟拖到第 38 分钟一次成功率 ≥95%。

### ② 首连页从"手打 URL"改成"发现 / 历史 / 扫码"三选一（M 成本，P0 收益）
- 现状：`activity_main.xml:125-141` 单输入框 + 一个按钮，说明文字对比度 4.00:1。
- 改法：优先做**局域网自动发现**（UDP 广播，桌面端加 20 行应答）→ 找到就直接列出"客厅台机 192.168.1.7"；兜底给最近 3 条历史地址；穿透地址单独一个 Tab 并解释"无需端口"。同时把说明文字提到 7.61:1 并做成"等待穿透 15–30s"的倒计时卡。
- 为什么最值：这是**每一个新用户的必经之路**，也是唯一"不做就没有用户"的页面；而且它把 `docs/redesign/mobile` 里所有"首屏好看"的成果挡在门外。
- 验收：新用户从安装到看到影片列表 ≤ 3 次点击、0 次键盘输入（同一 WiFi 下）。

### ③ 移动端动效与玻璃"预算表"（M 成本，全局体感收益）
- 现状：172 条 animation / 410 条 transition / 131 处 backdrop-filter，手机端只关了 2 条（`mobile.css:497-498`）。
- 改法：新增 `mobile-motion-budget.css`，在 `@media (max-width:860px)` 内：关掉极光/桌宠/view-loader 的 V1+V2、`backdrop-filter` 全部降为"不透明度 0.85 的实色面板"（保留 TabBar/播放器底栏/详情 header 三处玻璃）、统一过渡时长 120–180ms。
- 为什么最值：它同时买到**流畅度**（中低端机不再掉帧）、**可读性**（暗底正文不再被毛玻璃衬灰）和**风格一致性**（手机不再像"卡顿的桌面版"），且是纯 CSS 覆盖、可一键回滚（删文件即恢复）。
- 验收：千元机上首屏可交互 <1.5s、滚动 ≥50fps；暗色下 12.5px 灰字在 `backdrop` 面板上的实测对比度 ≥4.5:1。
