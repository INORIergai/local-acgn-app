# CinemaVault 安卓端 v4.6.0「稳与私」实施记录

日期：2026-10-22　版本：`versionCode 4` / `versionName 4.6.0`　产物：`CinemaVault-v4.6.0-Android.apk`（5,841,571 B）

本文件记录 [00-总报告](00-总报告.md) 里「四件必做」中属于 v4.6.0 起步波的落地情况，只写实际改了、实际测过的内容。

---

## 一、一句话结论

安全层从「谁都能下发安装包、应用只认 URL 不认人」变成「只认自己的签名 + 校验哈希 + 只允许同源页面碰原生桥」；首屏从「最长等 300 秒语音」变成「0.8 秒放人」；APK 从 debug 签名变成自有 release 签名，并且打包、版本号、分发校验全部收敛到一条命令、一个来源。

## 三、服务端与前端（由两名协作 Agent 完成，我复核了实测数据）

- `routes/app-update.js` 100 → 291 行：版本号从 `android/app/build.gradle` 现场解析（剥注释后正则，失败才回退）；候选包名收敛为 `CinemaVault-v<ver>-Android.apk` / `CinemaVault-Android.apk`，**硬拒** `app-debug.apk` 与任何 `build/` 路径；去掉 `D:\` 硬编码；下载改 `res.sendFile`（拿到 Range/ETag）；新增 `apkSha256` / `apkSize` / `signerSha256`（apksigner 现算 + 落盘缓存）。
- `server.js` +158 行零依赖 gzip 中间件：文本/json/js/svg、>1KB 才压；跳过 HEAD、Range、已有编码、304/302/401；带 `Vary`。实测 `app.js` 1904 KB → 228 KB，`style.css` → 14.7 KB。
- `public/js/app.js`：`ensureHls()` 按需注入（普通 mp4 完全不加载 404 KB 的 hls.min.js）；启动门重写为「只等片库首卡，3 秒硬上限，跳过按钮启动即可点」；语音改后台预热 + 右上角角标，安卓壳不预热、首次点朗读才启动。
- `public/library.html`：删掉同步 `<script src="lib/hls.min.js">`（脚本数 33 → 32）。

## 四、验证（可复现）

```powershell
# 构建 + 校验（读 build.gradle 版本 → assembleRelease → 复制到根目录 → 打印 sha256 → apksigner verify）
powershell -ExecutionPolicy Bypass -File packaging\build-android.ps1

# 产物自查
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\*\aapt.exe" dump badging CinemaVault-v4.6.0-Android.apk | Select-String versionName,debuggable
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\*\apksigner.bat" verify --print-certs CinemaVault-v4.6.0-Android.apk
```

实测结果：

- `versionCode='4' versionName='4.6.0'`，输出里**没有** `application-debuggable`；
- `apksigner` → `CN=CinemaVault`，证书 SHA-256 `699fe4c5…a4d865`（不再是 `CN=Android Debug`）；
- `/api/app/android-version` → `{"version":"4.6.0","versionCode":4,"apkSize":5841571,"apkSha256":"c21d1b1f…e396","signerSha256":"699fe4c5…a4d865","apkExact":true,"versionSource":"android/app/build.gradle"}`；
- 下载端点：Range 请求返回 `206` + `Content-Range: bytes 0-15/5841571` + `X-Apk-Sha256`，且 Range 响应不压缩；
- 首屏启动门：headless Chromium 实测 **0.82s** 揭开（桌面与安卓 UA 一致），`pageerror` 0。

**未做真机验证**：本机 `adb devices` 为空，无设备可冒烟。原生改动的验证止于「编译通过 + 产物属性正确」，触摸、文件选择、外链跳转需装到手机上确认。

## 五、升级与回滚

- **⚠️ 从 4.5.6 升到 4.6.0 必须先在手机上卸载旧版**：签名从 debug 换成 release，包名相同但证书不同，`INSTALL_FAILED_UPDATE_INCOMPATIBLE`。卸载会清掉应用内保存的影库地址，装完重填（用 `cinemavault://` 深链可跳转）。
- **密钥必须备份**：`android/keystore/cinemavault-release.jks` + `android/keystore.properties`（口令在文件里）。这两个文件已被 `.gitignore` 排除、**没有进入仓库**。丢了它们，以后所有版本都无法覆盖安装，只能再让用户卸载一次。
- 回滚：`git revert` 本提交后重新打包即可；若只想退回旧安装包，根目录仍保留 `CinemaVault-v4.5.6-Android.apk`。
