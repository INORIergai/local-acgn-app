# Cinema Vault 前端功能诊断与改进建议

> 范围：PC 桌面版（Electron 壳 + 本地 Express + `public/` 静态前端）
> 方法：静态代码审阅（架构、加载链、渲染路径、鉴权链路、Electron 主进程），未做运行时压测；文中数据均可在仓库中复核。
> 日期：2026-11-21

---

## 0. 结论摘要（TL;DR）

这是一个**功能密度极高、工程韧性很强**的个人媒体库应用：扫描/刮削/播放/阅读/云盘/AI/TTS/追番/在线观看都在一个应用里打通了，而且做了大量真实场景的防御（GPU 崩溃降级、渲染进程无响应自愈、SQLite FTS 损坏自动修复、更新包签名校验、单实例锁）。

但前端是典型的**长期叠加式演进**：

| 指标 | 现状 |
|---|---|
| `library.html` 首屏 CSS | **83 个** `<link>`，全部在 `<head>` 同步阻塞 |
| `library.html` 首屏 JS | **46 个** `<script>`（仅 5 个 defer），无打包、无代码分割 |
| 前端 JS 总量 | 45 个文件 / **42,125 行**；`app.js` 单文件 **19,672 行** |
| 前端 CSS 总量 | 89 个文件 / **32,558 行** / 约 1.4 MB |
| `!important` | **2,873 处** |
| `app.js` 内 `fetch(` | **246 处**，只有 **6 处**走统一的 401/DB 自愈包装 |
| `setInterval` | 全部脚本合计 **44 个** |
| 手动版本号 `?v=` | **128 处** |
| 内联事件/样式 | `library.html` 内 **70 处 `onclick`**、**155 处 `style=`** |

**最值得先做的五件事：**

1. **修复影片卡模板的 XSS 注入面**（刮削标题直接进 `innerHTML`/属性）。
2. **统一 API 客户端**：现在 246 处裸 `fetch`，401 会静默变成空列表。
3. **修搜索与视图切换的竞态**：慢请求会覆盖新结果。
4. **合并/压缩静态资源**：83 CSS + 46 JS 的请求瀑布是首屏最大的确定性成本。
5. **给静态资源做内容指纹 + 长缓存**，摆脱 128 处手工 `?v=`。

## 1. 架构与运行方式

```
┌─────────────────────────── Windows 桌面 ───────────────────────────┐
│  CinemaVault.exe                                                     │
│  └─ Electron 主进程 (packaging/main.js)                              │
│      ├─ 首次启动把 app 复制到可写数据目录（便携版跟 exe 走）            │
│      ├─ 用 ELECTRON_RUN_AS_NODE 拉起后端 server.js                    │
│      ├─ 等后端健康检查通过 → BrowserWindow → http://127.0.0.1:PORT/  │
│      └─ 崩溃/无响应/GPU 异常 → 自动降级、重载、重启                     │
│                                                                      │
│  后端 (server.js + routes/* + utils/*)                               │
│      ├─ Express 4，自写 gzip 中间件，静态托管 public/                  │
│      ├─ SQLite (better-sqlite3, WAL) + FTS5                          │
│      ├─ 扫描/刮削/转码/云盘/在线代理/AI Agent/TTS                      │
│      └─ 服务端会话鉴权（httpOnly cookie lml_session）                  │
│                                                                      │
│  前端 (public/)                                                       │
│      ├─ library.html：近似 SPA，switchView() 手工显隐 15+ 个容器        │
│      ├─ comic-reader.html / novel-reader.html / cloud-reader.html     │
│      └─ 原生 JS + 全局变量 + 脚本加载顺序约定，无框架/无构建            │
└──────────────────────────────────────────────────────────────────────┘
```

**值得肯定的设计：**

- 后端与 GUI 解耦，Android 壳可以直接复用同一套 HTTP 服务（`MainActivity` 只负责 WebView + 原生能力桥）。
- `packaging/main.js` 对桌面端真实故障做了系统性兜底：`ready-to-show` 不触发时 4 秒强制显示、GPU 进程崩溃写标记下次软渲染、渲染进程无响应自动强崩重载、单实例锁、外部链接交给系统浏览器。
- `server.js` 的 gzip 中间件对 Range/206/SSE 都做了豁免，避免视频 seek 被缓冲破坏。
- 更新链路做了 SHA-256 + 签名证书双校验（`routes/app-update.js`、`MainActivity`）。
- 每个"轮次"补丁文件都写了回滚方式，说明作者有意识控制风险。

**主要架构债：**

- 没有模块系统。45 个脚本靠"必须在 app.js 之前/之后"的注释维持顺序（见 `library.html:1224-1280`）。
- `app.js` 同时承担状态、路由、渲染、API、设置页模板、播放器、扫描 UI，职责过载。
- `switchView()`（`app.js:13443`）用 60+ 行手工 `style.display = 'none'` 管理视图，每加一个视图就要在每个分支补清理逻辑；仓库里 round26/round42c/round127 的修复注释正是这类遗漏的产物。

## 3. 诊断详述

### 3.1 安全：影片卡模板存在 XSS 注入面（P0）

`renderMovieCard()`（`public/js/app.js:671-746`）把外部来源的标题直接拼进 HTML：

```js
const displayTitle = prefTitle(movie);   // 可能来自刮削站、文件名或用户编辑
...
<div class="movie-card ..." title="${displayTitle}">
  <img ... alt="${displayTitle}" ...>
  <div class="movie-hover-title">${displayTitle}</div>
  <div class="mtb-main-title">${displayTitle}</div>
```

`prefTitle()`（`app.js:663`）返回 `originalTitle` / `cvDisplayTitle(movie)` / `movie.title`，**没有转义**。项目里已经有 `escapeHtml()`（`app.js:3472`），但这里没用。

后果不是理论问题：

- 标题来自 JAV/TMDB/Bangumi/网盘等外部数据源，任意一个源返回含 `"` 或 `<img onerror=...>` 的标题即可注入。
- 应用运行在 Electron 里，页面同源可调用本地 `/api/*`，包括删除、重命名、写配置等写操作。
- 同类风险还出现在 `bookSub`、`metaLine`、`bookBgStyle` 的 `url('...')` 拼接。

**建议：**

1. 所有文本插值统一走 `escapeHtml()`；属性值额外做引号转义。
2. `bookBgStyle` 不要拼 CSS，改用 `img`/`background-image` 的 `style.backgroundImage = 'url("' + encodeURI(...) + '")'` 或 `CSS.escape`。
3. 更彻底的做法：渲染层改成 `textContent` / `<template>` + `cloneNode`，只对富文本（简介）保留受控的 HTML 白名单。
4. 服务端出口再加一道：刮削入库时对 `title/originalTitle` 做长度与字符清洗。

> 另：`server.js` 未设置 CSP / X-Frame-Options / X-Content-Type-Options。考虑到页面大量内联脚本，短期可先加 `X-Content-Type-Options: nosniff` 和 `Referrer-Policy`，CSP 用 `Content-Security-Policy-Report-Only` 逐步收紧。

### 3.2 功能健壮性：401 静默失败与竞态（P0/P1）

**（a）401 静默变空列表。** `api` 对象（`app.js:217-437`）的每个方法都是：

```js
const res = await fetch(...);
const data = await res.json();
return data.data || [];
```

服务端会话过期时返回 `401 {"code":-1}`，`data.data` 为 `undefined` → 返回 `[]` → 页面显示"没有内容"，不会拉起 `Gate.onUnauthorized()`。只有 `fetchJsonWithDbHeal()`（`app.js:11124`）处理了 401，而全仓 246 处 `fetch(` 里只有 6 处走它。

**建议：** 封装一个 `request()`：统一 `res.ok` 判断、401 → `Gate.onUnauthorized()`、超时、JSON 解析失败、错误 toast。业务层只调 `request`/`api`。

**（b）搜索竞态。** `handleSearch()`（`app.js:17260`）只做了 300ms 防抖，没有 `AbortController` 或请求序号：

```
输入 "a" → 请求 A（慢）
输入 "ab" → 请求 B（快）
B 先返回并渲染 → A 后返回，把结果覆盖成 "a" 的结果
```

**建议：** 维护 `searchSeq`，返回时比对序号；或每次 `AbortController.abort()` 上一次请求。

**（c）视图切换竞态。** `switchView('movies')` 后立刻切到 `'jav'`，`loadMovies()` 的 `await` 返回后仍会 `renderMovies()`，把影片渲染进 AV 视图。`loadMovies()`（`app.js:13873`）等函数在 `await` 后没有校验 `currentView`。

**建议：** 每个 `load*` 函数在 `await` 后加 `if (currentView !== view) return;`；或引入 `viewToken` 自增校验。

**（d）加载失败无兜底。** 上述 `load*` 函数没有 `try/catch`。后端重启/掉盘时 `fetch` 抛错 → unhandled rejection → 界面停在旧内容，用户不知道发生了什么。

**建议：** 统一在 `request()` 层 toast + 空态，不要让 Promise 静默失败。

### 3.3 首屏与运行时性能（P1）

**（a）请求瀑布。** `library.html` 头部 83 个 CSS、尾部 46 个 JS。桌面版虽然是 localhost，但仍有：

- 83 次 CSS 解析 + 层叠计算（32,558 行、2,873 个 `!important`）；
- 46 次脚本请求与顺序执行（42,125 行），其中 `app.js` 19,672 行是解析大头；
- Electron 每次冷启动都要重新走一遍（HTML 被设为 `no-cache`，静态资源 `express.static` 未设 `maxAge`，见 `server.js:250`）。

**建议（不重写业务）：**

1. 引入 **esbuild/Vite** 只做"打包 + 压缩 + 指纹"，保留现有全局脚本写法（IIFE/全局函数照旧），按顺序 concat 成 1-3 个 bundle。
2. CSS 同样合并成 1-2 个文件，去掉开发期注释后再压缩。
3. 产物用内容 hash 命名，`express.static` 设 `maxAge: '1y', immutable: true`；HTML 保持 `no-cache`。这一步可以一次性消灭 128 处手工 `?v=`。
4. 首屏必须的脚本内联/预加载，非首屏模块（追番、云盘、TTS、Live2D、弹幕）改为动态 `import()` 或按视图懒加载。

**（b）渲染方式。** `renderMovies()`（`app.js:796`）用 `movies.map(renderMovieCard).join('')` 一次性 `innerHTML`，然后 `bindMovieCardClicks()` 给**每张卡**单独 `addEventListener`（无事件委托）。当前页 50 张尚可，但搜索/收藏/时间线可能几百张，重绘 + 绑定的成本线性上升。

**建议：**

- 卡片点击改为容器级事件委托（`closest('.movie-card')`）。
- 大列表引入分批渲染（`requestIdleCallback`/分页）或轻量虚拟滚动。
- 海报目前是原图直出，建议服务端生成 320px 缩略图（`sharp` 未必需要，可用 ffmpeg）或至少限制 `img` 尺寸 + `srcset`。

**（c）轮询。** 44 个 `setInterval`，其中 `checkScanStatus` 每 1.5s 一次且常驻（`app.js:18540` 附近）。建议：扫描空闲时降频到 15-30s，扫描中再加速；页面隐藏（`document.hidden`）时暂停。

### 3.4 CSS 与视觉系统（P1）

现状是"每一轮加一个覆盖文件"：

- 89 个 CSS 文件，文件名 `round13` … `round153`，加载顺序即优先级；
- 2,873 个 `!important`，大量样式靠"最后加载 + 强行覆盖"生效；
- 5 个文件未被 `library.html` 引用：`reader-settings.css`、`round74-reader.css`（阅读器用）、`round113-p7.css`（已评估撤回）、`tokens.css`、`style.v2-backup.css`（备份，应移出 `public/`）。

**影响：** 改一个按钮颜色可能影响 10 个页面；新功能不敢删旧规则，只能继续加文件；`style.v2-backup.css` 这类文件还会被 `express.static` 直接暴露。

**建议：**

1. **先止血**：把 `.bak` / `.backup-*` / `_lab` 预览页移出 `public/`（或加 `.gitignore` + 打包排除）。
2. **建令牌层**：`tokens.css` 已存在但未引用，先把颜色、间距、圆角、字号、动效时长收敛进去。
3. **按层拆分**：`base → layout → components → views → overrides`，新代码只允许进对应层，禁止无理由 `!important`。
4. **逐步合并 round 文件**：按视图把覆盖规则并回主文件，一次一个视图，用截图回归验证。
5. 引入 Stylelint 禁止新增 `!important`（存量加白名单）。

### 3.5 可访问性（P1/P2）

已有进步：`round122-a11y.js` 给卡片补 `tabindex/role/aria-label`，`round123-nav.js` 给详情弹窗做了焦点陷阱；海报灯箱、批量重命名抽屉有 `role="dialog" aria-modal`。

仍存在的缺口：

- **详情弹窗** `#detailModal`（`library.html:742`）没有 `role="dialog"` / `aria-modal` / `aria-labelledby`。
- **密码门禁** `gate.js:60` 的 `#gateModal` 没有 `role="dialog"`，没有焦点陷阱，Tab 可以跑到背后的页面；关闭后也没有把焦点还给触发元素。
- 70 处内联 `onclick` 让键盘/读屏语义不可控，且无法统一做 CSP。
- `switchView` 用 `display:none` 隐藏视图，但不管理 `aria-hidden`/`inert`，读屏仍可能读到隐藏内容。
- 颜色对比度只在 `round125-contrast.css` 局部修正，缺少系统性检查。

**建议：** 抽一个 `Dialog` 小工具（打开时记录来源焦点、设置 `aria-modal`、Tab 循环、Esc 关闭、关闭归还焦点），详情/门禁/播放器/重命名统一接入；把内联 `onclick` 逐步改成 `data-action` + 委托。

### 3.6 桌面端特有体验（P2）

Electron 壳整体质量高，但有几个明显的桌面用户预期未满足：

1. **窗口尺寸/位置不持久化**：`createWindow()`（`packaging/main.js:712`）固定 `1560×940`，没有 `getBounds/setBounds`、没有最大化状态恢复。用户每次启动都要重调窗口。
2. **没有系统托盘**：最小化即任务栏，后台扫描/下载时缺少"驻留"入口。
3. **缩放不持久化**：菜单只有 `zoomIn/zoomOut/resetZoom`，重启回到 100%。
4. **无全局快捷键**（如 `Ctrl+Shift+Space` 呼出/隐藏窗口），对媒体库应用是高频需求。
5. **菜单未随主题/语言统一**：`buildMenu` 里中文标签与 Electron role 混用，可读性一般。
6. **更新提示与前端更新提示是两套**（`mobile-updater.js`、`updater.js`、`app-update.js`），需要确认桌面版只走一条链路，避免重复弹窗。

**建议优先做 1 + 3**（半小时级改动，体验收益最大），再评估托盘与全局快捷键。

### 3.7 资源与发布卫生（P2）

- `public/` 内混有 `app.js.bak-nr`、`polish.css.bak-nr`、`style.v2-backup.css`、`.backup-novel-reader-101840.html`、`_magic-preview.html`、`_r79_paperback_lab.html`、`_sq-motion-lab.html`。这些都会被 `express.static` 提供，也会进入 `payload/` 打包体积。
- 根目录有大量 `_rNNN-*.js/.json/.log` 诊断脚本与日志，建议移到 `scripts/`、`logs/`（部分已忽略，但仍在工作区）。
- `.sync-cv451.ps1`、`git/`、`exe/`、`backups/` 等目录混在仓库根，建议明确"源码 / 产物 / 诊断"分区。

**建议：** 在 `prepare-export.js` 里加显式排除清单；在 `.gitignore` 里补 `public/**/*.bak*`、`public/**/.backup*`、`public/_*-lab.html`；把 `style.v2-backup.css` 移到 `archive/`。

### 3.8 观测与测试（P2）

- 没有全局 `window.onerror` / `unhandledrejection` 上报；桌面版虽然有 boot 日志，但前端运行时异常只进控制台，用户看不到，开发者也只能靠"复现"。
- 没有单元测试/E2E；仓库里的 `_rNNN-verify.js` 是手工 Playwright 脚本，未纳入统一入口。
- 建议：加一个轻量前端错误采集（写入 `sessionStorage` + 设置页"导出诊断"），并把现有 verify 脚本收敛成 `npm run verify:ui`。

## 4. 改进路线图

### P0（建议本周完成，改动小、收益大）

| # | 事项 | 落点 | 验收标准 |
|---|---|---|---|
| 1 | 影片卡模板全量转义 | `app.js:671-746` | 标题含 `<img onerror>` / `"` 时不产生 DOM 注入；引号不破坏属性 |
| 2 | 统一 `request()` / API 客户端 | `app.js:217-437` | 401 一定拉起门禁；超时/JSON 失败有 toast；`fetch(` 裸调用逐步归零 |
| 3 | 搜索与视图竞态保护 | `handleSearch`、`load*` | 快速输入/快速切视图时只渲染最后一次结果 |

### 5.1 统一请求层（示意）

```js
// core/request.js
async function request(url, options = {}) {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), options.timeout || 15000);
  try {
    const res = await fetch(url, { ...options, signal: ctrl.signal });
    if (res.status === 401) {
      window.Gate?.onUnauthorized?.();
      throw new Error('会话已过期，请重新验证');
    }
    const text = await res.text();
    const data = text ? JSON.parse(text) : {};
    if (!res.ok || data.code < 0) throw new Error(data.msg || `请求失败（${res.status}）`);
    return data;
  } catch (e) {
    if (e.name === 'AbortError') throw new Error('请求超时');
    throw e;
  } finally {
    clearTimeout(timer);
  }
}
```

单实例唤起在 `win-unpacked` 打包产物上验证通过（第二个实例 5 秒内被合并、已有窗口唤起）；
便携版因每次启动要重新解压，第二个实例 15 秒内还没完成解压，脚本判定超时——属于单文件封装的固有延迟，不是逻辑差异。
短启动（`win-unpacked`）下主窗口 7.8s 出现，可作为安装版参考。

### 9.7 桌面体验第二批（2026-11-21）

**播放时阻止息屏**

- 监听 `webContents` 的 `media-started-playing` / `media-paused`，播放期间 `powerSaveBlocker.start('prevent-display-sleep')`，暂停/结束立即释放；窗口隐藏或关闭时也会释放，避免后台音频一直吊着电源。
- 不轮询、不需要 preload/IPC，交给 Chromium 的媒体状态事件，误判少。
- 探针实测：`powerSaveBlocker.start` 返回有效 id、`isStarted` true，stop 后 false；带静音循环音频的页面能稳定触发 `media-started-playing` 与 `media-paused`。

**后端自愈补强**

- 原逻辑只在进程启动成功时清零计数；现在后端**稳定运行超过 10 分钟**后再崩溃会重置额度，避免跨天累计 5 次后自愈被永久关闭。
- 额度用完不再只是写日志：弹窗提供「重启后端 / 打开日志 / 稍后处理」，重启会清零计数、等后端就绪后自动刷新界面。
- 菜单/托盘「重启后端服务」也一并清零计数，手动恢复后自愈重新可用。

**开机自动启动（可选，默认关）**

- 应用菜单「文件」与托盘右键菜单都增加「开机自动启动」复选项，写系统登录项（Windows Run / macOS 登录项），勾选后以 `--hidden` 启动。
- `--hidden`：跳过启动动画、主窗口保持隐藏、首次运行/快捷键冲突/代码同步等启动弹窗全部跳过，只驻留托盘；托盘创建失败时自动改为正常显示窗口，避免「启动后哪都找不到」。
- 便携版用 `PORTABLE_EXECUTABLE_FILE`（原始 exe）登记，不会指向临时解压目录；开发模式和未打包环境不显示该菜单项。
- 实际验证（Electron 38）：登录项写入后 `getLoginItemSettings` 返回 true，取消后 false；`electron . --hidden` 启动 20 秒内可见窗口数为 0，日志记录「主窗口保持隐藏 / 跳过启动动画 / 系统托盘已创建」，按 `Ctrl+Shift+F12` 后出现「本地影库」主窗口，进程无异常。
- 打包版（`electron-builder --dir`）复测：`--hidden` 启动 25 秒可见窗口 0、托盘创建、`Ctrl+Shift+F12` 唤出主窗口；随后正常启动可见窗口 1、托盘创建、启动日志完整、无 `!!!` 异常。

说明：验证机 `Ctrl+Shift+Space` 被占用的概率不低（输入法/截图工具），所以回退链路不是纸面功能，是实际会走到的路径。
「快捷键已调整」提示只在首次遇到时弹一次（记录在数据目录 `shortcut-notice.json`），避免每次启动都弹模态框。
